## 2. 运行时架构

### 2.1 全局单例 `DB`（`:3112`）

整个应用只有一份运行时数据对象 `DB.data`，它就是 `bzr_workbench_v1` 反序列化后的结果。核心方法：

| 方法 | 行号 | 语义 |
|---|---|---|
| `DB.table(k)` | `:3326` | 取表，缺失时懒建空数组 |
| `DB.add / update / remove` | `:3330–3354` | 表内增删改；`add` 一律 `unshift` 到数组头部 |
| `DB.find(key,id)` | `:3352` | 按 id 查，**未命中返回 `undefined`** |
| `DB.save(silent)` | `:3276` | 60ms 防抖后写 localStorage |
| `DB.load()` | `:3136` | 返回 `'override' / 'restored' / 'recovered' / 'seed'` |
| `DB._migrate()` | `:3228` | 结构补全（详见 §3.2） |

**数据与渲染的耦合方式**：页面 `render()` **同步**读 `DB.table()` 拼 HTML 字符串；表单提交**同步**改 `DB.data` 后调 `DB.save()`，再整页 `rerender()` 重画。没有状态层、没有事件总线、没有观察者。因此改造的核心动作就是：把这层「同步直读直写」替换为「异步调 API」。

### 2.2 页面注册与路由

- 页面注册表是普通对象 `PAGES`（声明于 `:6214`），每个键只被赋值一次（已全量核验，无重定义、无覆盖）。
- 页面对象契约：`{ title, sub, icon, nav, navSub?, noNav?, render }`。
- **`render()` 必须返回 `{ html, bind(root) }`** —— 只返回字符串会渲染成空白（`go()` 只取 `res.html`，`:17849`）。`bind` 可省。
- 路由是哈希：`#<pageKey>`；切换用 `history.replaceState`（`:17895`），不产生历史记录，`file://` 下失败静默忽略。
- `go(page)`（`:17837`）：未注册页回落 `home`（唯一的路由守卫）；`render` 与 `bind` 各自 try/catch，渲染失败出错误卡片，绑定失败只弹 toast。
- `rerender()` = `go(CURRENT)`（`:17907`）：**整页重建 DOM，监听器、滚动位置、输入焦点全部丢失**（页面里多处靠 `setTimeout` 抢焦点来补偿）。
- 侧栏由 `buildNav()`（`:17727`）生成，`NAV_ORDER`（`:17669`）定分组顺序；`'系统'` 分组已声明但无页面使用。
- 页面可见性：`pageVisibility` 根键 + 页面管理弹窗（`:18087`）可隐藏任意页，但 `go()` **不做可见性守卫**，`#hash` 深链仍可进入。

### 2.3 通用组件层（改造时最值得保留的资产）

**没有**名为 `table()`/`form()` 的函数，等价物是：

- `renderCrudPage(cfg)`（`:5522`）→ `{ html, bind }`，`bindCrud` 内绑定搜索（`:5794`）、筛选、排序、分页、新增、导入、导出、批量选择、虚拟滚动（`:5886`）。
- `openForm(cfg, row, prefill)`（`:4430`）：`row` 有值即编辑；字段渲染 `fieldHTML`（`:4128`），取值 `readForm`（`:4212`）；提交直接 `DB.update/DB.add`（`:4484`）。
- 字段类型：`text / number / textarea / select / checkbox / date / photo / images`；`photo` 压到 240px，`images` 压到 1200px，结果都是 data URL。
- 其他：`openModal`（`:4048`）、`confirmBox`（`:4090`）、`openDetail`（`:4512`）、`toast`（`:3082`）、`openImageLightbox`（`:4412`）、`makeStudentModule(spec)`（`:5962`，自动注入学生选择器 + 按姓名回填学号）。
- `cfg` 契约字段（这是改造时最需要保持兼容的接口）：`key, title, sub, entity, columns[{k,label,render,csv,numeric,sortable,w,cls,syn}], fields[{k,label,type,options,required,default,full,hint,readonly,numeric}], filters, detail, selectable, cardView, pageSize, defaultSort, searchKeys, beforeTable, afterTable, headActions, validate, beforeSave, afterSave, onImportRow, onKpi, formCols, formSub, formSize`。
- UI 状态（搜索词/排序/页码/筛选/视图）另存于 `TState`（`:5244`）与批量选择集 `_sel`（`:5600`），与持久数据分离 —— 改造时这部分应留在前端。
- 图表：**全部手写内联 SVG**（`lineChart` `:6000`、`barChart` `:6086`、`sparkline` `:6152`），零第三方图表库；Canvas 只用于图片压缩。

## 3. 存储机制

### 3.1 现状

- 业务数据唯一键：`const KEY = 'bzr_workbench_v1'`（`:3106`），一个 JSON 装下**所有**表、所有图片。
- 写入：`DB.save()` 60ms 防抖（`:3278`）→ `localStorage.setItem` → 可选文件写入 → 自动备份。
- **落盘空窗**：全文件没有 `beforeunload` / `visibilitychange` / `pagehide` 兜底，改动后 60ms 内关页会丢这一次改动。
- 自动备份：**IndexedDB**（库 `bzr_fs_store` / store `kv`，`:3392`），快照键 `bak_<timestamp>`，保留最近 **5** 份，写入节流 5 分钟；损坏时可自动恢复（`:3174`）。
- 可选真实文件模式：**File System Access API**（`showSaveFilePicker`，`:3118` 能力探测 / `:3680` 使用），`<handle>.createWritable()` 写 JSON（`:3638`）；句柄本身也存进同一个 IndexedDB（`fileHandle`，`:3726`）。**两种模式都保留 localStorage 镜像**作兜底。
- 配额超限（`:3286`）：捕获 `QuotaExceededError` → toast 明确告警 + 建议改用本地文件模式 + 强制写一份 IndexedDB 备份；**不裁剪、不清除**数据。
- 图片一律 data URL 入库，入库前用 canvas 压缩（头像 240 / 多图 1200 长边、JPEG 0.82，`:4258`）；设置页的占用条按 **5 MB** 估算（`:16711`）。

### 3.2 `_migrate()` 做了什么（`:3228–3272`）

1. 数据不是对象或是数组 → 整体重置为种子深拷贝；
2. 以种子为模板**只补 `undefined` 的根键**（不多删）；
3. 补 `meta`；4. `meta.version = APP_VERSION`（只是标记，每次打开都刷新）；
5. `delete data.deeds`；6. `fees[].ledger` 补空数组；7. `countdowns` / `cdHidden` 补数组；8. `todos/contacts/visits/templates/classact` 补数组。

**没有按版本号分支的升级逻辑**——「版本迁移」目前只是结构补全。这是改造时必须补上的能力。

### 3.3 导出形态

- 表格导出：`.xlsx`（SheetJS），库不可用时降级为带 BOM 的 CSV（`:4790`）。
- 整库导出：`JSON.stringify(DB.data)`（`:17269`）；恢复时只校验 `obj.students` 是否存在（`:17291`），**不校验各表结构**。
- **导出为自带数据的独立 HTML**（`buildPortableHtml()`，`:4666`）：把 `DB.data` 序列化后转义 `<`、注入 `__SEED_OVERRIDE__`，再把软件源码从页面内的 `<div class="appsrc-chunk">`（base64 分块）还原并重新拼装，得到一个「双击即用、数据内嵌」的单文件；顺带把授权 UI 替换为空函数。打开时 `DB.load()` 命中 `__SEED_OVERRIDE__` 分支直接采用（`:3142`）。

## 4. 网络行为（会议分析的悬置问题，此处给出结论）

**无埋点、无统计上报、无业务数据外传。** 全文件无 XMLHttpRequest、WebSocket、EventSource、sendBeacon、无第三方统计 SDK、无外部 `<script src>` / `<link href>`。存在的联网点只有三类：

1. **本地 exe 后端的相对路径接口**（仅在 `window.__BZR_EXE` 或 `127.0.0.1` 下触发）：`POST /api/save_file`（`:4596`）、`GET /api/config`（`:18463`）、`POST /api/backup`（`:18729`）、`GET /api/pick_folder`（`:18751`）、`GET /api/open_folder`（`:17381`）、`GET /api/pick_data_dir`（`:17405`）。
2. **公网 CDN**：课程表图片 OCR 动态加载 `https://cdn.jsdelivr.net/npm/tesseract.js@5.1.0/...`（`:11643`），仅用户点击该功能时加载，离线不可用。
3. **授权激活云函数**：腾讯云函数 `https://1462379364-...ap-guangzhou.tencentscf.com`（`:18489`），激活/解绑时发送激活码 + 本机随机指纹；localhost 时改走 `/api/*` 代理。不上传业务数据。

**授权层与业务数据完全隔离**（注释明确「铁律：绝不碰 `bzr_workbench_v1`」，`:18409`）：`__BZR_FREE` 短路使 `getState()` 直接返回 `'official'`（`:18527`），业务读写路径（`DB.load/save`、`go()`、各页面）**没有任何授权判断**。唯一耦合是备份工具函数挂在 `Lic` 命名空间下（`Lic.pickFolder` / `openBackupFolder` / `__bzrBackup`）。**结论：去掉授权层不影响任何业务功能与数据。**

### 5.4 关联方式（改造的第一原则）

几乎所有跨表关联都是**按姓名**：`attendance / seats / dorms / youth / cadres / health / grants / discipline / talks / contacts / visits` 都存 `name`（大多另有 `sno`，但 `sno` 多由 `beforeSave` 从学生表单向回填，编辑姓名后即失联）。`conflicts.parties` 是顿号分隔的姓名字符串，学生档案里的「矛盾参与」用 `parties.includes(name)` 匹配，**姓名互为子串时会误挂**（`:8844`）。

删除学生**没有级联清理**：`seats / cadres / youth / duty / contacts` 里按姓名关联的记录会变成孤儿。

## 7. 已确认的缺陷清单

按性质分四类，均为改造时的修复依据。

### 7.1 崩溃类（异常进全局兜底，产出「意义不明」提示）

| 位置 | 触发条件 | 后果 |
|---|---|---|
| `:13824` | 点「✎ N人间」改宿舍容量，调用 `window.prompt()` | exe/CEF 环境 `prompt()` 常被禁用或抛异常 → 兜底 toast `出错了：…` |
| `:13861` | 点宿舍床位卡片，`DB.find('dorms', id)` 返回 `undefined` 后直接取 `.name` | `Cannot read properties of undefined` |
| `:13611` | 列表视图点删除，`find` 未命中后 `esc(row.name)` | 同上 |
| `:13607` | 列表视图点铅笔，`find` 未命中 → `openForm(cfg, undefined)` | 把「编辑」变成「新增」，数据翻倍且无提示 |
| `:17931` | 全局错误兜底：任何未捕获异常统一 toast `出错了：<msg>` | 用户看到的就是「意义不明的报错」 |

### 7.2 静默错数据类（不报错，但结果错）

| 位置 | 问题 |
|---|---|
| `:13685` / `:13503` / `:13515` | 宿舍容量 `Number(x.capacity) \|\| 8`，默认值 8 硬编码三处；种子无该字段 → 全部回退 8 人间 |
| `:13830`–`:13845` | 容量写在该房间「数组顺序第一条」记录；分组键 `building\|room` 字符串拼接，未命中时**仍提示成功** |

### 7.3 口径不一致类（同一业务，多处算法不同）

| 业务 | 不一致点 | 行号 |
|---|---|---|
| 出勤 | 今日看板/趋势/代课简报：缺席 = 当天 `病假/事假/旷课` 的**记录条数**，出勤率 = (全班人数 − 缺席条数)/全班人数；但本月 KPI 计**全部 5 类**（含迟到/早退）；首页跟进只认 `handled` 为空的记录；学生档案按 5 类分别计数 | `:9852` / `:6380` / `:10198` / `:6460` / `:7602` / `:8814` |

| 作业 | `homework.rate`（手填）与 `courses[].homework[].rate`（另一份手填）并行 | `:11919` / `:14689` |

### 7.4 硬编码与能力缺口

- **常量写死**：`WEEKDAYS` 只有周一~周五（`:6216`），但值日安排的 `weekday` 允许选周六/周日（`:11125`）→ 周末值日在概览卡里不可见；`PERIODS` 8 节（`:6218`）与出勤的 period 选项是两套硬编码（`:9782`）；`SUBJECTS` 9 科（`:6220`）。
- **农历表只到 2028 年**（`:7324`）→ 2029 起倒计时的自动假期项只剩公历节日。
- **教室名/团支部名拼接**：`meta.grade + meta.classNo + '教室'` 散落多处（`:11337`、`:11601`、`:11835`、`:11259`）。
- **新学生默认学号** `'2024' + (人数+1).padStart(3,'0')`（`:9470`），与 `meta.year='2026-2027学年'` 不一致。
- **默认值有偏**：新增学生默认 性别男 / 住校 / 共青团员（`:9468` 附近）。
- **无算法**：座位「排位原则」只是展示文本，随机排位会**清空备注**（视力/身高等信息丢失）；值日安排**不存在轮换逻辑**，`duty` 是 weekday×area 静态表。
- **媒体能力**：只有图片，且以 base64 存在 localStorage；**没有任何录音能力**（无 `MediaRecorder` / `getUserMedia` / `capture=`）。
- **打印**：通用工具栏没有打印，各页自行绑定 `window.print()`（座位表、代课简报等）。
- **导入**：无事务，逐条写入，中途失败不回滚；表头匹配靠同义词字典（`FIELD_SYNONYMS`，`:4922`）+ 两遍匹配，必须识别出 `name` 或 `sno` 才允许导入（`:5182`）。
- **设置页清空数据**只清 `SEED_DATA` 里存在的键（`:17617`），运行时懒建的其它表会被整体丢弃。
