# 05 · 运行环境与后续事项

> 本文记录用户对运行环境的决定，以及**明确推迟到后续阶段**的事项。
> 结论先行：跑在**老师自己的电脑**上；**部署环境不联网**（客户要求）；**无账号、无口令、无备份**；数据只在本地。

## 2. 已接受的取舍（记录在案，避免以后被当成疏漏）

| 取舍 | 后果 | 状态 |
|---|---|---|
| 不设访问口令 | 同一局域网内任何人只要知道地址和端口，就能查看并修改全班学生与家长信息 | **用户已知情并接受**，「有需求了再说」。地址不是秘密 —— 这是本方案最大的安全缺口 |
| 不做备份 | 硬盘损坏、系统重装、误删 = 数据全丢且无法恢复 | **用户已决定推迟**。唯一缓解：数据就在 `data/` 目录，可自行整目录拷走（零开发量，见 §3） |
| 不用 HTTPS | 局域网内流量明文，可被同网段嗅探 | 接受 |
| 服务依赖机器开机 | 手机端可用性受限于那台电脑是否开着 | 接受，不设计开机自启 |
| 推迟部署打包 | 本轮交付的是「能在开发机跑起来的项目」，老师还不能自助安装 | 见 §4 |

> 无口令、无备份、无 HTTPS 这三条都是**明确决定**，不是遗漏。将来若要在学校里更大范围使用，需要重新评估 —— 尤其第一条。

## 3. 数据就在本地（本轮最简约定）

- 数据目录里是 `workbench.sqlite` + `media/` + `logs/`。**整目录拷走 = 完整备份**，这是本轮唯一的「备份」方案。
- 界面上放一句说明：数据目录在哪、怎么整包拷走 —— 不做按钮、不做加密、不做自动备份。
- 「清空数据」前提示一次，避免误操作（属于防误触，不算备份功能）。
- 恢复 = 把拷走的目录放回去，写进使用说明即可。

### 4.1 一键启动包（已落地，第六阶段）

**形态**：一个目录，自带 Python 运行时，老师**解压后双击**就能用 —— 不装 Python、
不装数据库、不装 Docker（离线环境也装不了），也不需要管理员权限。

```
班主任工作台/
├── 启动.bat / 启动.command             ← 老师只认这几个：双击
├── 后台启动.* / 停止.* / 状态.*
├── 设置开机自启.* / 取消开机自启.*
├── launcher.py                        ← 所有逻辑在这一个文件里（跨平台）
├── runtime/                           ← 自带的 Python 3.11 与全部依赖（交付时构建）
├── backend/ frontend/ docs/            ← 程序代码（tools/ 是开发用的，不进交付包）
├── data/                              ← **老师的全部数据**（数据库/照片/录音/日志）
├── 使用说明.md                         ← 给老师看的一页纸
└── README.md / CONTRIBUTING.md / docs/ ← 给开发看
```

**为什么是这个形态**（三个被排除的方案）：

- **Docker**：老师的电脑上装不了（离线、没有运维），排除；
- **桌面外壳（Electron/Tauri）**：`README` 与 `03` 早已明确不做，界面就用系统浏览器；
- **PyInstaller 打成单文件 exe**：macOS 侧必须在 Mac 上构建与验证（我们手上没有 Mac），
  Windows 侧还容易被安全软件误报；出问题时老师只能干瞪眼，而「目录 + 脚本」能直接看日志与数据。

**launcher.py 一件件干的事**：找空闲端口（8723 起，被占就往后找）→ 建数据目录 →
显示「这台电脑 / 手机」两个地址 + Windows 防火墙提示 → 打开浏览器 →
**已经在跑时只打开浏览器**（老师最常见的动作是再点一次，不该报错）→
`--daemon` 真脱离终端（Windows 无窗口、macOS 脱离会话）→ `--stop` / `--status` / `--install-autostart`。

**后台与自启**：Windows 用注册表 `HKCU\...\Run`（无需管理员，登录后无窗口跑起来，
任务管理器里显示「班主任工作台」）；macOS 用 `~/Library/LaunchAgents/` 的 LaunchAgent
（登录即起、崩了自动重启）。**都不需要管理员/root**。

**数据目录**：`<包根>/data/`（**不是 `backend/data/`**，第六阶段改的）—— 老师一眼看得懂
「数据在这儿」，备份就是拷这一个目录。开发机上直接跑 uvicorn 也用同一个默认值
（`app/config.py` 的 `DATA_DIR`），可用 `TWS_DATA_DIR` 覆盖。

**怎么构建**（`tools/build_bundle.py`）：下 python-build-standalone 的可搬移运行时 +
按 `requirements.txt` 下轮子（缓存在 `vendor/`，可离线重建）+ 组装 + 收拾行尾权限 + 打 zip，
构建完**自己起一次服务验一遍**。Windows 产物约 48 MB。`pip download` 那一步需要一个**联网的构建机**
（这正是 §5.2 说的「在联网的开发机上把依赖预先拉到本地」）。

**手机怎么知道该输哪个地址**：地址口径只有一处（`services/access_info.py`），
启动窗口会把它打出来**并附一张终端二维码**（拿手机相机/微信扫一下就等于打开）；
界面「设置 → 手机访问」里有同一张二维码（内联 SVG）与一个「复制地址」按钮。
二维码用 segno（纯 Python、无依赖、MIT）本地生成 —— **不能引 CDN 上的二维码脚本**，
那种东西在离线环境里一定加载失败。

**多网卡（VPN / 虚拟机）**：内核挑的「默认出口网卡」未必是手机能访问的那张，
所以本机所有 IPv4 都作为候选列出来（探到的排第一）—— 界面「手机访问」里有
**「换一个地址」**，黑窗口里也会把候选打出来；接口 `?address=` 只认**本机**地址
（否则就成了任意二维码生成器）。

**被别的工具启动**（一键启动器、定时任务、WorkBuddy 这类 AI 助手）：`launcher.py` 提供
稳定接口 —— `--daemon`（幂等，已在跑就返回 0）、`--status --json`（机器可读，不要求解析中文）、
`--stop`、`--install-autostart`；环境变量 `TWS_PORT` / `TWS_DATA_DIR` / `TWS_HOST`；
自检地址 `/api/v1/health`。细节见 `CONTRIBUTING` §10.3 与 `使用说明.md` 第五节。

**Python 环境**：老师那边**不装、也不碰他的 Python** —— 交付包自带一份可搬移的 CPython
（`runtime/`），运行期只用它，不写 PATH、不装包、不碰全局 site-packages；
脚本在找不到 `runtime/` 时**明确报错**而不是退回系统 Python（开发机要退回得显式设
`TWS_ALLOW_SYSTEM_PYTHON=1`）。包外的写入只有老师主动点的「开机自启」那一项。

**还没做的**：**macOS 上的真机验证与构建**
（macOS 的包必须在 macOS 上构建 —— 它的运行时压缩包含符号链接，在 Windows 上解压会坏；
脚本会明确拒绝而不是假装成功）。

## 5. 运行环境与前端基线

### 5.1 目标机器：老师自己的电脑

原先考虑过学校的 32 位 Windows 7，**已改为用老师自己的电脑**。这一改动解除了一串原本很硬的约束：

| 原约束（32 位 Win7） | 现在 |
|---|---|
| Python 只能用 3.8.10（官方支持 Win7 的最后一版） | **Python 3.11**，与团队现有 `.validation/conda` 环境一致 |
| 32 位轮子稀缺，`pydantic-core` 等可能装不上 | 64 位轮子齐全，**技术选型不受影响** |
| 浏览器上限 Chrome 109 | 现代浏览器（基线见 §5.3） |
| 转写依赖 PyTorch（无 32 位轮子）→ 在目标机上不可行 | 若那台电脑性能够，**PyTorch / FunASR 可用**，录音转写重新成为可行的后续增强项（仍不在本轮） |

### 5.2 离线是**硬要求**（客户不希望部署的服务器联网）

这不是「机器老、上不了网」，而是**部署环境的网络策略**：客户不希望这台服务器联网，默认在离线环境里使用。因此它是一条**架构约束**，不是可以放宽的前提。

**设计规则（本轮就要遵守）：**

1. **运行期零外网依赖。** 代码里不得出现任何指向外网的地址：CDN、字体、图标、统计上报、在线更新检查、远程授权 —— 一个都不行。启动后拔掉网线，全部功能必须照常。
2. **开发期可以联网，但不得引入运行期依赖。** 我们的开发机有网没问题；关键是别把「联网才能跑」的东西写进去。
3. **依赖必须能整体带走。** 目标机器不能 `pip install`，所以要在联网的开发机上预先 `pip download` / `pip wheel` 把全部后端依赖拉到本地目录（`vendor/` 或 `wheels/`），随项目一起交付。一键启动包推迟了，但**这条从第一天就要成立**。
4. **升级 = 手工替换文件**，没有任何在线更新机制。

**唯一受影响的功能：课程表图片 OCR。** 原应用是动态加载 `cdn.jsdelivr.net` 上的 tesseract.js（`:11643`），离线环境下**不可能工作**。处理方式（推荐第 1 种）：

1. **默认关闭**，界面上明确写「此功能需要联网，当前环境不可用」，不要静默失败、也不要报错吓人；
2. 若确实需要，把 tesseract.js 与中文语言包（`chi_sim`，几十 MB）一起打包进本地静态资源 —— 但这会明显撑大交付包，且本轮没这个需求。

> 静态资源继续用内联 SVG 图标 + 系统字体栈，天然满足离线要求。

### 5.3 前端基线

- 目标：**主流现代浏览器**（近两年的 Chrome / Edge / Firefox，以及对应的手机浏览器）。
- 可以放心用：ES modules、`fetch`、可选链 `?.`、空值合并 `??`、CSS Grid / Flex、`dialog`、`<audio>` 原生播放。
- 但注意：**部署环境不联网 → 浏览器不会自动更新**。所以仍要避免最近才落地的实验特性（容器查询、View Transitions 之类），并且手机端可能是旧一点的系统浏览器。
- 手机端要在**真实手机**上验收（`03` §4.2）。

## 6. 安全边界（简化版）

| 项 | 措施 |
|---|---|
| 网络暴露 | 服务在局域网内可达；**不出公网，不做端口映射**。注意：同网段任何人都能访问 |
| 访问保护 | **不做**（无账号、无口令）—— 用户已知情并接受，风险见 §2 |
| 外网依赖 | **运行期完全不联网**：零埋点、无 CDN、无云调用、无自动更新、无远程授权。这是客户的硬要求，也是隐私上的加分项 |
| 授权层 | 原应用的试用 / 授权与远程激活**整体删除**（本来就要联网，也留不了） |
| 数据位置 | 数据、媒体、日志都在那台电脑上，不经过学校服务器或任何第三方 |
| 备份 | **本轮不做**，见 §2、§3 |
| 删除 | 软删除 + 回收站；提供「彻底删除某学生全部数据」的入口；清空前提示 |
| 日志 | 不记姓名、电话、身份证、媒体路径 |
